An rsync example to back up Linux boxes in Maths at UoB

Assembled by Márton Balázs, IT rep for Maths
last updated: [2019-09-27 Tue]

This page is here to demonstrate an efficient way of backing up your documents with rsync to our Linux servers in the School of Mathematics. This is just how I do it, there are various other ways and comments are of course always welcome! Be careful and always test your method first to avoid data loss. To review the servers available to us, and set up ssh to connect from in and out of the UoB, please take a look at here.

The main idea is that we don't want to move files by hand as a backup since this is slow and prone to errors. Instead we ask rsync to compare files and upload incrementally those that have a newer version locally. Throughout, [username] is your UoB username in the format ab12345.

If you don't yet have this, create a tmp/ directory in your home, this is where sync logs will be written. Create a file somewhere which we'll call [exclusion file]. This will tell rsync which parts of your home you want to exclude from the backup. Contents of this one look like 

.*
tmp/
public_html/

as you definitely don't want all the hidden dotfiles to be uploaded, nor your tmp directory. If you have a local copy of your webpage at public_html, this might go to the server personal-webpages instead of e.maths. There is a lot more you can do in this file, the rsync man page has a long section on this.

Then create a script and make it executable so that you can run it from a terminal with the following contents: 

#!/bin/bash

k=`date +%N`

while true
do
 read -s -p "TEST to e.maths [enter]; s: skip " nos
 if [ "$nos" == "s" ]; then
  echo "TEST to e.maths skipped"
  break
 elif [ -z "$nos" ]; then
  echo "___________________ TEST to e.maths ___________________" 2>&1|tee -a ~/tmp/sync_tmp$k.txt
  rsync --timeout=120 -nrvauzzi --progress --no-group --exclude-from=/home/[username]/[exclusion file] -e ssh /home/[username]/ [username]@e.maths.bris.ac.uk:/home/[username]/ 2>&1|tee -a ~/tmp/sync_tmp$k.txt
  echo "^^^^^^^^^^^^^^^^^^^ TEST to e.maths ^^^^^^^^^^^^^^^^^^^" 2>&1|tee -a ~/tmp/sync_tmp$k.txt
  break
 fi
done

if [ -f ~/tmp/sync_tmp$k.txt ]; then
 [your preferred text editor/viewer here] ~/tmp/sync_tmp$k.txt
fi

where [your preferred text editor/viewer here] could be less, more, gedit, pico, emacs, vim, etc. (My line here uses Vim and the MultipleSearch plugin, it reads 

 vim "+noremap q :q" "+noremap  " -c 'Search TEST' -c 'Search ^...st' -c 'Search ^.....p' -c 'Search ^..+++++++++' -p -M -R ~/tmp/sync_tmp$k.txt

:-) ) The script gives you an opportunity to skip if you change your mind, I find this useful. It then runs rsync which looks at your files on e.maths, and uploads anything from your local machine's HOME that is either missing or newer than on e.maths and is not excluded in the [exclusion file]. The options we used are:
--exclude-from= to exclude files and directories you listed in [exclusion file].
-nrvauzi, these are several options that I found useful for rsync over ssh and for listing the actions. They also forbid rsync to remove anything on e.maths that's missing locally. Check the man pages for various possibilities.
--timeout=120, this limits your wait if something goes wrong with the network connection.
--progress, this shows how files are being transferred, useful with big ones.
--no-group, I added this when I figured that groups on e.maths and the local machine don't match.

The pipe into tee writes a copy of whatever the script shows you into a file in tmp/ of a random name that comes from the current time. Finally, the script shows you this file so that you can comfortably look into it. These files are not removed so eventually you'll have to clean your tmp/.

Actually, the above script doesn't do anything except showing you what would happen if you were serious, se let's call it emathssynctest. To do the real thing, make a copy and call it emathssync in which you remove "TEST" everywhere and replace -nrvauzi by -rvauzi.

It is also useful to compare your local files to those on e.maths, i.e., run the script backwards. This is simply achieved by swapping /home/[username]/ and [username]@e.maths.bris.ac.uk:/home/[username]/ above, and change "to e.maths" to "from e.maths". This will show you if there is a file on the server that's missing locally, and if you are on multiple machines you could use this to make sure all desktops are kept synced.

Finally, changing the rsync line to 

  rsync --timeout=120 -nrvauzzi --progress --no-group -e ssh /home/[username]/public_html/ [username]@personal-webpages.maths.bris.ac.uk:/home/[username]/public_html/ 2>&1|tee -a ~/tmp/sync_tmp$k.txt

can be used to upload your maths webpage from your local machine.
