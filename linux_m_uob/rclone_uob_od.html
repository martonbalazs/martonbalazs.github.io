Using rclone to connect Linux boxes at the UoB to OneDrive

Assembled by Márton Balázs, IT rep for Maths
last updated: [2021-10-01 Tue]

There are various servers described here that can be used for file storage. This page explains a way to connect Linux boxes to OneDrive. I wouldn't call this a full backup as OneDrive does not respect several Linux conventions such as capitalisation, file timestamps and permissions. Nevertheless, this could be useful to provide all your files should you need them on UoB Windows machines as MyFiles will terminate soon. Be careful and always test your method first to avoid data loss.

Here we'll use rclone to copy files from the Linux home to OneDrive.

Step 1: Currently the version of rclone is too old on the Ubuntu 18.04 and 20.04 machines (I don't know about CentOS, I don't have one handy to test). Hence, after opening a terminal (with Bash please), do 

 module load rclone

Step 2: Proceed along this guide. The default options as described worked fine for me. I called the remote "onedr", and in OneDrive I have a directory called rclonesync where I want my Linux files to be uploaded.

Step 2a: Following the introduction of MFA, rclone might greet you with a frightening error that contains the word oauth2. Following these steps, namely 

 rclone config update onedr env_auth true

(obviously replace "onedr" by your remote's name if it's different), seems to prompt the Authenticator app and solve the problem.

Step 3: If you don't yet have this, create a tmp/ directory in your home, this is where sync logs will be written. Create a file somewhere which we'll call [exclusion file]. This will tell rclone which parts of your home you want to exclude from the backup. Contents of this one look like 

.*
tmp/

as you definitely don't want all the hidden dotfiles to be uploaded, nor your tmp directory. There is a lot more you can do in this file.

Step 4: Create a script and make it executable so that you can run it from a terminal with the following contents ([username] is your UoB username in the format ab12345): 

#!/bin/bash

module load rclone

k=`date +%N`

echo "___________________ TEST Onedrive ___________________" 2>&1|tee -a ~/tmp/sync_tmp$k.txt
rclone sync --checksum -u -v --dry-run --exclude-from /home/[username]/[exclusion file] /home/[username]/ onedr:/rclonesync/ 2>&1|tee -a ~/tmp/sync_tmp$k.txt
echo "^^^^^^^^^^^^^^^^^^^ TEST Onedrive ^^^^^^^^^^^^^^^^^^^" 2>&1|tee -a ~/tmp/sync_tmp$k.txt

[your preferred text editor/viewer here] ~/tmp/sync_tmp$k.txt

where [your preferred text editor/viewer here] could be less, more, gedit, pico, emacs, vim, etc. (My line here uses Vim and the MultipleSearch plugin, it reads 

vim "+noremap q :q" "+noremap  " -c 'Search TEST' -c 'Search deleting' -c 'Search copying' -c 'Search directory' -p -M -R ~/tmp/sync_tmp$k.txt

:-) ) The script runs rclone which looks at your files on OneDrive/rclonesync/, and uploads anything from your local machine's HOME that is either missing or newer than that on OneDrive and is not excluded in the [exclusion file]. It also deletes from OneDrive files that are not present on your local Linux HOME. The options we used are:
--exclude-from to exclude files and directories you listed in [exclusion file].
--checksum, this uses a more accurate comparison than just size and modification time.
-u, this blocks a newer version on OneDrive from being overwritten by an old one from Linux, but I haven't tested this!
-v provides a list of what actually is changed.

The pipe into tee writes a copy of whatever the script shows you into a file in tmp/ of a random name that comes from the current time. Finally, the script shows you this file so that you can comfortably look into it. These files are not removed so eventually you'll have to clean your tmp/.

Actually, the above script doesn't do anything except showing you what would happen if you were serious, se let's call it onedrivesynctest. To do the real thing, make a copy and call it onedrivesync in which you remove "TEST" everywhere and also "--dry-run". Unfortunately this will also change the format of the output log of rclone (hence my last line there looks 

vim "+noremap q :q" "+noremap  " -c 'Search new)' -c 'Search existing)' -c 'Search ERROR :' -c 'Search : Deleted' -p -M -R ~/tmp/sync_tmp$k.txt

:-) )
